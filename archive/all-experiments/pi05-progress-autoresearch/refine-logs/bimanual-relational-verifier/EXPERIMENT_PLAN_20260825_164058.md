# 双臂关系状态 WAM 验证与纠错：实验计划

**问题**：π0.5 在长时双臂搬运中按 action chunk 开环执行，单臂延迟、双臂失配或物体姿态偏移后仍继续执行，导致失败。  
**方法命题**：动作条件的双臂—对象关系状态预测，比同预算的全局视觉 discrepancy 更早、更准确地发现物理关系失效，并在固定错误干预率与 policy 调用预算下改善闭环成功率。  
**日期**：2026-08-25  
**范围**：冻结 π0.5；第一版只做 event-triggered chunk truncation + re-query。关系归因后的专门恢复动作是第二阶段，不作为首轮必须成立的 claim。

## 路线卡

```yaml
representation: R4 explicit relational state, optional R3 visual latent encoder
control_use: U3 execution-time candidate/chunk verification
observations: [RGB or RGB-D, wrist/external camera, proprioception, executed-action history, language]
prediction_targets: [object pose, T_left_to_object, T_right_to_object, T_left_to_right, relation-event probabilities]
action_interface: future/committed dual-arm action chunk as conditioning input
rollout_horizon: one action chunk, evaluated at multiple sub-horizons
policy: frozen pi0.5
world_model_update: frozen at deployment
data_regime: existing offline trajectories + controlled simulator/real perturbations
primary_claim: structured relation prediction improves timely failure verification and closed-loop intervention over global visual discrepancy
main_failure_mode: relation proxy is inaccurate or pi0.5 cannot recover after correct intervention
```

## 系统定义

### 关系状态

图节点：左末端 `L`、右末端 `R`、被搬物体 `O`、目标区域 `G`。

连续边状态：

\[
x_t=\{T_O^t,T_{L\rightarrow O}^t,T_{R\rightarrow O}^t,T_{L\rightarrow R}^t,
\dot T_L^t,\dot T_R^t\}.
\]

离散/概率关系：

\[
p_t=\{p(r_{L,O}),p(r_{R,O}),p(r_{L,R}^{align}),p(r_{O,G}),p(slippage\text{-}proxy)\}.
\]

没有触觉时，所有 contact/support/slip 输出均称为 visual-proprioceptive proxy，不声称真实力或摩擦状态。

### 关系 WAM

输入最近 `K_obs` 帧的视觉特征、proprioception、已执行动作，以及 chunk 剩余动作；预测未来每个子步的相对 SE(3) 增量、关系事件概率与不确定性：

\[
p(x_{t+1:t+H},p_{t+1:t+H}\mid o_{t-K:t},q_{t-K:t},a_{t:t+H}).
\]

首版采用轻量 transformer/temporal graph head；视觉编码器冻结。必须另外训练同参数量 global-latent dynamics baseline。

### 部署干预

每 `m` 个低层控制步读取新观测，计算逐边 nonconformity：

\[
d_t^e=(\hat x_t^e-x_t^e)^\top\Sigma_e^{-1}(\hat x_t^e-x_t^e)
\]

并结合 relation-event probability 得到 risk。阈值在独立 calibration split 上设定为 5% episode-level unnecessary first intervention。触发后只做：截断剩余 chunk，重新调用冻结 π0.5。首轮不声称能生成 relation-specific repair action。

## 数据与标签

### 任务阶段

1. 双臂接近与建立相对抓持；
2. 抬升与稳定；
3. 水平搬运/绕过障碍；
4. 对准目标区域；
5. 放置和撤离。

### 故障族

| 类别 | 注入方式 | 应失效的主要关系 |
|---|---|---|
| 左臂滞后 | 对左臂动作加入延迟/缩放 | `L-O`, `L-R` |
| 右臂滞后 | 对右臂动作加入延迟/缩放 | `R-O`, `L-R` |
| 非对称抖动 | 单臂速度/位姿噪声 | `L-R`, object stability |
| 物体外扰 | 安全范围内改变箱体 pose | `L-O`, `R-O`, object trajectory |
| 支撑代理失效 | 小幅夹爪开度/相对滑移；仅在安全软载荷条件 | 对应 arm-object edge |
| 视觉负控制 | 光照、背景、相机轻微变化但物理执行正确 | 不应触发物理关系失败 |

### Ground truth

- `T_L,T_R`：forward kinematics；
- `T_O`：首轮使用 AprilTag/外部定位/仿真 state 作为**只用于监督和评价**的 ground truth，不能作为正式方法输入；
- relation label：根据相对 pose、共同运动、夹爪状态与任务阶段生成，并人工抽检；
- 数据按 episode 切分，禁止相邻帧跨 train/test；最终保留未见扰动幅度、物体质量和相机位姿 split。

## 实验块

### B0：Oracle headroom 与恢复能力

- **Claim tested**：正确检测并截断 chunk 是否有闭环价值。
- **Compared systems**：固定 chunk π0.5；周期性 re-query；oracle relation-failure trigger + re-query；oracle trigger + oracle safe stop。
- **Metrics**：受扰动任务成功率、恢复成功率、policy calls、完成时间。
- **成功门**：oracle trigger 相对固定 chunk 至少 +10pp 成功率，并且相对 matched-call periodic replanning 有正增益。
- **失败解释**：若不通过，检测不是当前瓶颈；检查 π0.5 是否见过恢复数据。必要时先收集 recovery demonstrations，停止训练 WAM。
- **位置**：最先运行；MUST-RUN。

### B1：关系接口与因果 sanity

- **Claim tested**：模型确实消费动作并预测正确关系。
- **Tests**：单任务 32-128 trajectories overfit；zero-action；action shuffle；只换左臂/只换右臂 chunk；SE(3) 坐标变换；视觉 nuisance 不改变物理关系。
- **Metrics**：分 horizon 相对 pose error、relation-event F1、action sensitivity、edge localization accuracy。
- **成功门**：真实动作条件优于 shuffled action；只扰动左臂时对应关系边的预测变化显著强于无关边。
- **失败解释**：动作被忽略或标签/时间对齐错误；禁止扩展训练。
- **位置**：MUST-RUN。

### B2：离线 matched-budget verifier 比较

- **Compared systems**：
  1. observation-only visual monitor；
  2. global action-conditioned latent WAM；
  3. object absolute-pose WAM；
  4. proposed relational WAM；
  5. oracle relation-state upper bound。
- **固定因素**：相同视觉编码器、输入模态、历史/预测 horizon、训练 episodes、参数量（±10%）、optimizer steps。
- **主指标**：5% episode false-intervention 下的 timely failure recall。
- **次指标**：AUPRC、检测延迟、failure-edge localization、NLL/Brier、risk-coverage curve、per-horizon pose/edge error。
- **成功门**：相对最强 learned baseline，timely recall +10pp；至少在两类物理故障和视觉负控制上成立。
- **位置**：Table 1；MUST-RUN。

### B3：闭环干预

- **Compared systems**：固定 chunk；matched-call periodic replanning；global WAM verifier；relational WAM verifier；oracle verifier。
- **协议**：配对初始状态和扰动随机数；固定 5% calibration target；匹配平均 policy invocation budget。
- **主指标**：受扰动 episode success。
- **次指标**：unnecessary intervention、time-to-intervene、post-trigger recovery success、完成时间、停滞率、调用次数。
- **成功门**：relational verifier 比最强 matched baseline 至少 +5pp success，且不靠更高 policy 调用频率。
- **位置**：Table 2；MUST-RUN。

### B4：机制消融与负控制

- 删除 `L-O`、`R-O`、`L-R`、`O-G` 各边；
- relative geometry → absolute poses；
- action-conditioned → observation-only；
- correct action → shuffled action；
- calibrated distribution → point estimate；
- graph head → 同参数 MLP/transformer；
- RGB-D → RGB（若正式方法使用 RGB-D）。

关键问题：收益来自“关系结构”，还是来自更多标签/深度/参数。MUST-RUN 只保留前四项；其余可进 appendix。

### B5：泛化与真实机器人压力测试

- 未见物体质量/载荷；
- 未见箱体尺寸；
- 相机外参、背景和光照；
- 不同搬运速度；
- 联合故障和长 horizon；
- 高风险条件先仿真/软载荷，真实机器人设置独立安全停止器。

指标按 prediction、calibration、decision、policy 三层分别报告，不能用预测指标代替控制结论。NICE-TO-HAVE，只有 B0-B4 通过后运行。

## Run Order and Milestones

| Milestone | Goal | Runs | Decision Gate | 估计成本 | 风险 |
|---|---|---|---|---|---|
| M0 | 数据/接口核验 | R001-R004 | FK、object pose、动作时间对齐通过；小样本可视化无错位 | 0-4 GPUh，1-2 天工程 | 标签错位会制造虚假 residual |
| M1 | Oracle headroom | R005-R008 | oracle trigger ≥ +10pp success；否则停止 verifier 路线 | 约 40-100 paired episodes | π0.5 没有恢复能力 |
| M2 | 关系 WAM sanity | R009-R014 | overfit、action shuffle、单臂干预全部通过 | 4-16 A100-GPUh | 模型忽略 action |
| M3 | 离线 pilot | R015-R020 | timely recall +10pp 信号 | 20-60 A100-GPUh | global baseline 等价 |
| M4 | 闭环 pilot | R021-R025 | success +5pp 且 matched calls | 60-150 paired episodes | 误触发/延迟抵消收益 |
| M5 | 3 seeds + stress | R026-R040 | CI 支持主张，视觉 nuisance 不产生大量误报 | 100-250 A100-GPUh；200-400 episodes | 分布偏移与安全成本 |

四张 A100 不必全部用于单次训练。轻量 verifier 首轮优先单卡/双卡并行不同 seed；仅在数据规模和 profiler 证明有收益时扩展到四卡。实际 wall-clock 取决于当前轨迹数量与图像分辨率。

## 第一批只启动的三个实验

1. **R001**：对 20 条轨迹绘制 `T_L→O`、`T_R→O`、`T_L→R` 与动作时间轴，人工检查标签和同步。
2. **R005**：固定 chunk π0.5 vs oracle relation trigger，在左右臂滞后两类故障上做 paired pilot。
3. **R009**：使用 privileged relation state 训练一个小型 action-conditioned dynamics head，并完成 correct/shuffled/zero-action sanity。

这三个实验都通过后，才值得接入视觉编码器并训练完整 relational WAM。

## 风险与处理

- **π0.5 不会恢复**：先收集少量“检测后重新稳定/重新抓取”示范；不要把检测失败和恢复失败混在一起。
- **视觉 contact proxy 不可靠**：主状态先用相对 pose 与共同运动；contact/slip 只做概率辅助头。
- **全局 WAM 已足够**：接受负结果，论文主张不能只剩结构更可解释。
- **额外 RGB-D 造成不公平**：所有核心 learned baselines 使用相同模态；另外报告 RGB-only 版本。
- **WAM 被 policy 利用**：本轮仅验证已提交 chunk，不在 WAM 中无限搜索；后续 reranking 必须单独做 selection-induced miscalibration audit。
- **真实机器人安全**：软载荷、速度/扰动上限、独立硬停止；安全停止器不计作方法成功。

## 明确暂缓

- 多对象 identity belief；
- 多候选 chunk reranking/MCTS；
- 触觉/力模型；
- 完整 4D occupancy tube；
- relation-specific learned repair policy；
- 跨本体迁移。

这些是长期 ACG-WAM 扩展，不进入第一轮因果验证。
