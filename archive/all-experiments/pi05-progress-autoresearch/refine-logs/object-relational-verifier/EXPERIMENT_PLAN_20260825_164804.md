# 通用对象关系 WAM 验证：修订实验计划

**修订原因**：方法不绑定“双臂搬箱”。双臂搬运仅是一个关系拓扑实例。  
**问题**：VLA 在不同操作任务中执行 action chunk 时，任务相关的对象关系可能建立失败或在执行中失效；全局视觉 residual 难以定位哪条关系出了问题。  
**方法命题**：语言选择的、可变大小的对象关系图，经 action-conditioned dynamics 预测后，能够跨任务检测关系建立/失效，并比全局视觉 verifier 更可靠地触发 replanning。  
**策略**：冻结 π0.5；首轮只研究 verification + chunk truncation/re-query。

## 通用状态表示

场景表示为动态图：

\[
G_t=(V_t,E_t).
\]

节点数量和类型可变：

\[
V_t=\{\text{robot effectors, objects, receptacles, tools, articulated parts, goal regions}\}.
\]

每个节点：

\[
v_i^t=[q_i\|c_i^t\|g_i^t\|u_i^t],
\]

- `q_i`：对象/部件地址；
- `c_i^t`：视觉与语义内容；
- `g_i^t`：pose、稀疏几何、运动；
- `u_i^t`：状态不确定性。

每条边表示两个实体之间的关系：

\[
e_{ij}^t=[T_{i\rightarrow j}^t,p(contact),p(support),p(inside),p(attached),p(aligned),p(occluded)].
\]

语言指令不要求模型预测所有边，而是选择任务相关子图：

\[
G_t^\ell=M(\ell,G_t)\odot G_t.
\]

例如：

| 任务 | 任务相关节点 | 关键关系边 |
|---|---|---|
| 杯子放入托盘 | gripper, cup, tray | gripper-cup, cup-tray |
| 打开抽屉 | gripper, handle, drawer | gripper-handle, handle-drawer/articulation |
| 推物体到区域 | gripper/tool, object, goal | effector-object, object-goal |
| 使用工具移动目标 | gripper, tool, target, goal | gripper-tool, tool-target, target-goal |
| 双臂搬运 | left effector, right effector, object, goal | L-object, R-object, L-R, object-goal |

因此双臂只是节点更多、关系组合更复杂的 stress test，不是固定方法接口。

## Action-conditioned graph dynamics

输入历史观测、proprioception、语言和 committed/candidate action chunk：

\[
p(G_{t+1:t+H}^\ell\mid G_{t-K:t},a_{t:t+H},\ell).
\]

模型预测：

- 任务相关对象的多步几何变化；
- 关系建立、保持、失效事件；
- 每条关系边的预测分布与不确定性。

部署时只对任务相关边计算 discrepancy/risk。超过校准阈值后截断当前 chunk 并重新调用 π0.5。

## 两个论文主张

| Claim | 最低证据 |
|---|---|
| C1：关系图 verifier 比 global visual/latent verifier 更准确地发现 action-conditioned 任务关系失败 | 固定 5% unnecessary-intervention，至少两个任务家族上 timely recall +10pp；action-shuffle 和 edge-shuffle 明显下降 |
| C2：同一个关系动力学接口能迁移到不同对象数量、关系类型或未见关系组合 | held-out task family 或 held-out relation composition 上仍有正增益，并在 matched policy-call budget 下闭环 success +5pp |

Anti-claim：增益不能只来自 ground-truth pose、更多深度、更多参数、更多 replanning 或某一个固定任务模板。

## 任务划分

第一版不需要覆盖所有应用，但至少选择三个不同 relation motifs：

### Family A：抓取—放置/包含

- pick-and-place；
- object-in-container；
- stack/support；
- failure：抓取未建立、途中滑落、放置后关系失效。

### Family B：推/工具介导关系

- direct push；
- tool-mediated push；
- target-to-goal；
- failure：接触未建立、错误对象运动、工具与目标脱离。

### Family C：关节或多执行器组合

二选一作为主实验，另一个进 appendix：

- articulated：door/drawer/handle；或
- bimanual：two-effectors/object/goal。

测试划分：

1. seen task + unseen layout/object；
2. unseen relation composition，例如训练 `gripper-object`、`object-container`，测试二者串联；
3. unseen graph cardinality；
4. camera/background nuisance negative control；
5. 可选 held-out task family。

## 实验阶段

### G0：关系状态是否具有控制 headroom

对每个任务家族使用 simulator/marker/FK 的 oracle relation state。比较固定 chunk、periodic replanning、oracle relation trigger。

GO 条件：至少两个任务家族中，oracle trigger 相对固定 chunk ≥ +10pp success，并优于 matched-call periodic replanning。若只在一个场景有效，不能声称通用关系接口。

### G1：可变图接口 sanity

- 单任务小样本 overfit；
- 节点顺序 permutation；
- 增删无关 distractor nodes；
- action shuffle/zero action；
- 只改变一个执行器或一个接触对象；
- edge label shuffle；
- SE(3) scene transform；
- 只改变视觉 nuisance。

通过条件：节点排列和无关节点不应明显改变任务边预测；动作/关系干预必须改变对应边而不是所有边。

### G2：离线 verification

Baselines：

1. observation-only visual monitor；
2. global action-conditioned latent WAM；
3. object node dynamics without relations；
4. fixed-schema relation model（每个任务单独训练）；
5. proposed shared variable-graph WAM；
6. oracle relation upper bound。

所有 learned baselines 匹配输入模态、视觉编码器、数据、参数量、history/horizon 与训练 steps。

主指标：timely recall at 5% episode-level unnecessary first intervention。  
辅助指标：event F1、edge localization、NLL/Brier、risk-coverage、horizon error、graph-size scaling、inference latency。

### G3：闭环 verification + re-query

比较固定 chunk、matched-call periodic replanning、global WAM verifier、shared relational WAM、oracle verifier。

主指标：按任务家族分别报告受扰动 success，不只报告总平均。  
辅助指标：恢复成功率、检测延迟、false intervention、完成时间、policy calls、stagnation。

### G4：通用性和机制消融

Must-run：

- language-selected task subgraph → all edges；
- relations → object nodes only；
- variable shared graph → per-task fixed schema；
- action-conditioned → observation-only/shuffled；
- relative geometry → absolute pose；
- held-out relation composition 与 graph cardinality。

若 per-task fixed-schema model 与 shared graph model 相当，仍可主张任务内 verifier，但不能主张通用关系 WAM。

## 推荐运行顺序

| 阶段 | 内容 | GO/KILL |
|---|---|---|
| M0 | 为 A/B/C 各选择一个任务，定义 oracle nodes/edges/events | 标签必须能稳定复现 failure |
| M1 | 三类任务 oracle trigger headroom | 至少两类任务 ≥ +10pp success，否则收窄 claim |
| M2 | privileged-state variable graph dynamics | permutation、distractor、action-shuffle 测试全部通过 |
| M3 | 视觉关系 WAM + matched offline baselines | 至少两类任务 timely recall +10pp |
| M4 | 闭环 pilot | matched calls 下 success +5pp |
| M5 | held-out composition/cardinality + 3 seeds | 通用性 CI 支持 C2；否则降为 task-specific method |

## 首先执行的三个实验

1. 为 `pick-place`、`push/tool`、`articulated 或 bimanual` 各选一个现有任务，画出节点、边和成功/失效事件；检查同一图接口能否表达三类任务。
2. 在三类任务分别运行 oracle relation trigger；确认不是只有双臂搬箱受益。
3. 用 privileged state 训练一个可变节点数 graph dynamics head，测试节点 permutation、添加 distractor、action shuffle 和 held-out relation composition。

只有这三项通过，才接入 SAM/DINO/RGB-D perception。这样先验证的是“通用关系接口”，而不是某个场景的对象检测质量。

## 暂缓内容

- identity posterior 与主动消歧；
- 多候选 chunk 搜索/MCTS；
- 触觉和真实接触力；
- 完整 4D occupancy tube；
- learned targeted recovery policy；
- 所有任务一次性大规模联合训练。

这些可以在通用 relation verifier 成立后逐层增加。
