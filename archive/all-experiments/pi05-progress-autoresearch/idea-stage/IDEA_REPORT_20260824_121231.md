# Idea Report：Policy-Conditional Commit Regret

## 一句话 Idea

长时 VLA 的进度写入不应只按“这个完成判断是否正确”训练，还应区分它对固定执行策略造成的未来控制伤害；通过同一环境快照的 `commit/suppress` 配对 rollout 测量该伤害，再训练轻量 gate 决定何时把不确定进度暴露给 π0.5。

## 为什么来自真实问题

π0.5 在长任务里出现重复、跳步、错误完成和失败后继续推进。普通 memory 解决“是否保留历史”，completion head 解决“是否预测完成”，但二者通常把所有标签错误近似等价处理。实际上，一个无关步骤的轻微误判和一个会让后续策略跳过关键前置条件的误判，其闭环代价完全不同。

## 核心假设

在固定 policy 下，候选进度写入的事实误差与控制伤害并不完全一致，而且伤害呈异质或重尾分布。用多步 policy-conditional regret 训练 admission gate，会比等容量的 truth/calibration gate 更少触发高代价错误推进。

## 最小方法

1. 冻结 π0.5（或另一可复现 VLA）、恢复逻辑与 rollout 预算。
2. 在自然阶段边界和失败边界保存完整 simulator snapshot。
3. 只改变一个候选断言是否写入 policy-facing task context，使用 common random numbers 运行配对未来。
4. 定义 `ΔJ = J(commit) - J(suppress)`；分别保留成功、无效/重复动作、oracle-action regret，不先任意混成一个分数。
5. 用部署时可见的执行前后观察、动作 chunk、候选断言、truth uncertainty 预测 `ΔJ` 或 harm rank。
6. 真值约束优先：明显为假的断言不得因短期“有帮助”而提交；regret 只用于不确定候选的风险排序与选择性提交。

## WAM 的位置

主 Idea 不需要 WAM。WAM 只可作为可选的短视野 label generator 或 harm predictor，并必须在相同数据、参数、推理延迟和调用次数下击败：

- calibrated truth verifier；
- one-step action-disagreement；
- discriminative short-horizon value critic；
- geometry/VLM postcondition judge。

若不能，删除 WAM，不影响主 claim。

## 贡献边界

不声称首个 memory selector、completion gate、decision-focused learning 或 causal memory intervention。唯一主贡献是：在 VLA 进度写入场景中定义和验证 paired-snapshot policy-conditional commit regret，并证明它是否提供 truth accuracy 之外的控制信息。
