# GISS-2x2: Matched-State Geometry-Action Compatibility for Frozen Robot Policies

**Method.** Matched-State Geometry-Action Crossover (GISS-2x2)

## Motivation
A frozen VLA (vision-language-action) policy can appear robust across geometry changes for different reasons. It may use visible functional geometry to choose its current action, follow an open-loop default that happens to work, or recover later through closed-loop feedback. Aggregate success cannot tell these explanations apart because changing geometry usually also changes the resulting state trajectory, contact dynamics, and inference history. The key problem is therefore to measure whether the current action is compatible with a particular geometry while holding the decision state fixed and using the same native success criterion in every comparison. RoboTwin 2.0 and GemBench make this problem observable, but ordinary rollout comparisons do not provide the four counterfactual cells needed to ask whether the chunk elicited by geometry A works better in A than the chunk elicited by endpoint-equivalent geometry B, and vice versa. GISS-2x2 supplies this narrow matched-state diagnostic for frozen policies.

This diagnostic is practical now because RoboTwin 2.0 provides broad, editable functional geometry and reproducible task families, while GemBench and Any3D-VLA make 3D generalization a current evaluation target. Local open frozen policies such as OpenPI pi0.5 and CLOVER can also be queried repeatedly without training or paid application programming interfaces. Together, simulator state serialization, collision-mesh editing, and deterministic inference controls make a four-cell checkpoint crossover feasible at a scale that still permits manual validation of geometry pairs.

Prior work stopped short of this comparison for structural reasons. RoboTwin 2.0 studies dataset or rollout performance rather than a within-state counterfactual estimate of current action compatibility. GemBench changes the condition being solved through split-based evaluation instead of creating crossed cells that cancel recipient difficulty. CoA-VLA places an explicit affordance structure inside the policy rather than measuring an unmodified frozen policy. Any3D-VLA evaluates representation and end-to-end behavior without supplying the matched checkpoint, action swap, and recipient-controlled contrast. CLOVER studies reactive recovery, where error detection, replanning, and downstream feedback remain entangled with the original action choice.

Closing this gap would provide a policy-agnostic assay that separates geometry-conditioned current actions from open-loop defaults and later recovery. The finding would remain localized to eligible task families rather than becoming one broad capability score, and it would identify where native success specifically depends on a geometry-compatible first action chunk.

### M0_background
*Set the preregistered scope, build controlled geometry instruments, and establish a restore-tested matched decision state before running the crossover.*

For every decision event, record a unique identifier, task family, fingerprints of the instruction and terminal test, executable event detector, allowed pre-action phase, fixed exclusion codes, action-block length in controller ticks, baseline-success numerator and denominator, minimum accepted support, and baseline-stratum boundaries. Validate the file with a JSON Schema, freeze a cryptographic fingerprint, and output both the registered file and the machine-readable event grammar.
   - _Why:_ The claim is deliberately limited to this instrument. Fixed eligibility rules stop a small diagnostic from being presented as a broad claim about VLA competence.
2. For every registered task and endpoint-equivalent group, create one unchangeable pair record. Store a pair identifier, task family, A/B asset identifiers, visual-material descriptions, fingerprints of the collision meshes, all mass, inertia, friction, joint, and actuator settings, fingerprints of the instruction, object identities, initial state, and terminal test, plus a certificate listing every endpoint field compared and its tolerance.    - _Why:_ The functional pairs create the source intervention, while the appearance-only pairs test whether a result is merely caused by rendering sensitivity.
3. When the registered decision event fires, save checkpoint z as a typed snapshot. Include robot joint positions and velocities, object poses and velocities, controller accumulators, task-state-machine state, simulator clock and integrator state, sensor state, and every random-number-generator state. Keep the selectable A/B geometry handle outside the shared state. The output index contains the checkpoint location, snapshot version, cryptographic fingerprint, pair and event identifiers, geometry-selection key, and full invariant audit.
   - _Why:_ Holding the decision state fixed prevents open-loop state or dynamics mismatch from being counted as geometry-conditioned action compatibility.

### M1_matched_state_crossover
*Query geometry-conditioned chunks from one checkpoint, execute all four source-recipient cells, and estimate the recipient-controlled compatibility interaction.*

4. For each source $s\in {A,B},$ restore z, select geometry $G_{s},$ and build the same fresh history template $h_{0}.$ It contains the registered instruction, current shared proprioception, and current rendered observation, while all earlier observations, earlier actions, recurrent state, and Key-Value (KV) cache fields are explicitly empty. Load the same frozen policy in evaluation mode, use identical preprocessing and decode seed $\xi ,$ and return chunk $u_{s}$ as a typed native-action array with its shape, control mode, coordinate frame, units, controller rate, valid-step mask, and fingerprint. The current description does not define a runnable decoder or repeatability test. 【author decision: preregister the policy-specific sampler or decoder, number of repeats, shared-seed rule, distance d between equal-shaped action arrays, per-action-dimension normalization, and tolerance $\epsilon _{det}.$】 Repeat each unchanged render under that exact configuration, calculate all pairwise distances, and accept it only if the largest distance is no greater than $\epsilon _{det}.$ Save the configuration, seeds, chunk fingerprints, and distances, then destroy the policy instance and every recurrent, token, and KV cache before another query.

*Query the frozen policy at the same checkpoint z with a shared fresh history template $h_{0}$ and decode seed $\xi $; only the rendered source geometry $G_{s}$ changes.*
$$ u_s = \pi_\theta\!\left(o(z,G_s),h_0;\xi\right),\qquad s\in\{A,B\} \tag{1} $$


*An identical-render repeat must keep chunk variation below the preregistered determinism tolerance before the pair is eligible.*
$$ \max_{k,k'} d\!\left(u_s^{(k)},u_s^{(k')}\right) \le \varepsilon_{\mathrm{det}} \tag{2} $$

   - _Why:_ The visible source geometry should be the only cause of a changed chunk. Shared history, controlled decoding, repeated queries, and cache removal prevent hidden inference state or sampling variation from becoming the intervention.
5. Create exactly four execution records for every pair, policy, and reset seed: each recipient $r\in {A,B}$ receives the chunk from each source $s\in {A,B}.$ For one record, restore the same checkpoint and random-number-generator states, select recipient geometry $G_{r},$ and send each valid command in $u_{s}$ unchanged through the policy's normal controller at the registered rate and action-block length. Do not add a geometry-specific coordinate conversion, and stop the injected block early only if the registered native terminal test fires. After injection, start a new frozen-policy instance and initialize it only from the actual recipient rollout, never from a source-query cache. The exact history required by a stateful policy is missing. 【author decision: specify for each policy which actual recipient observations and executed actions fill every history slot, how absent slots are padded, and which recurrent or cached fields are reset.】 Continue from the actual post-block observation until native success, native failure, or the registered episode limit. Save $Y_{r\leftarrow s}$ plus identifiers, checkpoint and chunk fingerprints, before/after observation fingerprints, executed actions, terminal reason and tick, binary success, and a clean-cache assertion.

*Cell $Y_{r\leftarrow s}$ is native task success when chunk $u_{s}$ is executed in recipient geometry r and the frozen policy then resumes from the actual post-chunk observation.*
$$ Y_{r\leftarrow s}=\mathbf{1}\!\left\{\mathcal{R}\!\left(z,G_r,u_s,\pi_\theta^{\mathrm{fresh}}\right)\models\tau\right\},\qquad r,s\in\{A,B\} \tag{3} $$

   - _Why:_ Within each recipient, the crossed cells change only which source produced the first chunk. Continuing from the real post-chunk observation avoids replay-prefix and stale-cache artifacts.
6. Make one complete four-cell group for each pair, policy, reset seed, and registered stratum, and use it only when all four eligible $Y_{r\leftarrow s}$ results are present. For that group, find the own-source minus cross-source success difference separately inside each recipient, then average the two differences to obtain the matched-state interaction $I_{MS}.$ Inside each task-family, policy, and endpoint-equal baseline stratum, first average reset seeds within a geometry pair and then give every geometry pair equal weight, so a pair with more seeds cannot dominate. To obtain paired uncertainty, enumerate every with-replacement resample of pair identifiers inside the stratum while always keeping all seeds and all four cells of each sampled pair together. Report the conventional two-sided 95% percentile interval, which does not require a Gaussian model for the binary differences. For each stratum, report the point estimate, interval, registered-pair count, complete-group count, and coverage: complete groups that passed the repeatability gate divided by all registered groups, with every exclusion counted by reason code. Do not combine strata into an overall effect that was not registered.

*The matched-state interaction averages each recipient's own-source advantage, canceling a recipient geometry that is simply easier.*
$$ I_{\mathrm{MS}}=\tfrac{1}{2}\left[\left(Y_{A\leftarrow A}-Y_{A\leftarrow B}\right)+\left(Y_{B\leftarrow B}-Y_{B\leftarrow A}\right)\right] \tag{4} $$

   - _Why:_ The symmetric interaction cancels the effect of one recipient geometry simply being easier and measures selective compatibility with the source geometry rather than raw success or raw action difference.
