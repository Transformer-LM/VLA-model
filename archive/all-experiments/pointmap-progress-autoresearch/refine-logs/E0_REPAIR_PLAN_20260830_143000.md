# E0/G0 structural repair plan

Date frozen: 2026-08-30 14:30 +08:00  
Trigger: CLAIMS_FROM_RESULTS.md = no / repair  
Scope: repair the representation diagnostic only; do not advance to E1/B2 and do not change the original positive G0 thresholds.

## Verified failures to repair

1. Learned Oracle contains raw absolute positions, quaternions and raw visibility counts; train-family z-normalization causes severe held-family shift.
2. PointMap feature vector also retains task/world-coordinate and scale-specific components although the decision only requires relative change and observability.
3. Validation predictions, threshold candidates and per-epoch traces are not stored.
4. Aggregate uncertainty uses a five-fold t interval instead of the registered task-cluster bootstrap.
5. A camera-shift edge case has zero post target visibility while retaining the continue label. Preserve it as a documented edge rather than silently relabeling after seeing results.

## Frozen structural changes

### R1. Deterministic invariant Oracle probe

Use simulator relative translation change and visibility only:

- retract if norm(delta(target-reference)) >= 0.09 m;
- otherwise reobserve if the target was visible before and has zero visibility in both post cameras;
- otherwise continue.

The 0.09 m threshold is fixed before implementation as half the generator's minimum scripted invalidation translation (0.18 m), not selected by test search. Required sanity: accuracy >=0.99 and macro-F1 >=0.98 on all 360 samples. Store predictions, confusion matrix, failures and code/data hashes.

### R2. Learned invariant Oracle

Replace the raw 48-D Oracle vector with domain-scaled task-invariant features:

- target translation delta and norm;
- reference translation delta and norm;
- relative translation delta and norm;
- per-camera binary target/reference visibility before/after;
- visibility loss flags.

Remove absolute positions, all quaternions and raw pixel counts. Scale translations by a fixed 0.30 m domain constant and do not fit family-wise z-normalization.

### R3. Learned invariant PointMap

For each camera retain only:

- binary target/reference visibility before/after;
- target and reference center-motion vectors/norms when observed;
- target-reference relative-change vector/norm when observed;
- explicit validity/missingness flags.

Use the same fixed 0.30 m scale and no family-fitted z-normalization. Keep the original addressed RGB and complete-Depth baselines unchanged.

### R4. Cheap invariant probes

Before the full grid:

- save the deterministic invariant Oracle result;
- run the learned invariant Oracle 5 folds x 3 seeds;
- save a deterministic PointMap relation probe under the same frozen 0.09 m rule as a diagnostic only;
- optionally run a linear invariant PointMap probe if the MLP and direct probe disagree.

These probes distinguish information loss from learner failure. They do not replace the registered four-modality G0 result.

### R5. Reproducibility traces

For every learned run save:

- best epoch and full per-epoch train loss/validation macro-F1;
- validation sample indices, labels and probabilities;
- every FRR threshold candidate with validation FRR and invalidation recall;
- selected threshold;
- test predictions and achieved test FRR;
- code, geometry, data, manifest, audit and common-config hashes.

### R6. Correct cluster-bootstrap statistics

Use task family as the resampling unit. For each modality and paired modality delta:

- average seeds within each fold;
- bootstrap five folds with replacement;
- 10,000 deterministic resamples with seed 20260830;
- report point estimate and percentile [2.5%, 97.5%] interval.

The original G0 pass/fail point thresholds remain unchanged. Bootstrap intervals are evidence, not a new post-hoc pass criterion.

## Run order and stopping

1. Static/AST checks.
2. Deterministic Oracle + PointMap probe on existing data.
3. Learned Oracle-only 5x3 repair pilot. Stop if Oracle F1 <0.75 or achieved test FRR >0.05.
4. Fresh-agent code review.
5. If Oracle passes, rerun all four modalities under one new trainer/geometry/config hash.
6. Aggregate with corrected bootstrap and rerun integrity/result-to-claim.
7. Enter E1/B2 only if the original G0 conditions all pass.

## Claim ceiling

Even a repaired G0 pass establishes only controlled simulator-mask PointMap headroom. It does not establish realized-trace value, WAM novelty, VLA improvement, recovery, closed-loop success or real-robot benefit.
