# 修订实验计划

## Claims

- C1：privileged property ceiling 表明物理响应在困难关联中存在可利用 headroom（仅必要条件）。
- C2：在完全相同允许历史下，显式 uncertainty-coupled system-ID factorization 优于 full-history action-conditioned GRU，并减少 wrong-object decision。
- Anti-claim：结果不是 body/slot 泄漏、唯一物性条码、更多参数、额外历史或大面积拒绝造成。

## M0：生成器与泄漏审计（MUST）

- 运行 MuJoCo spatial-pusher smoke；动作由世界坐标轨迹定义，只通过接触改变物体。
- 生成 200–2000 episode 小数据；每 episode 随机 address↔body、物性映射和检测顺序。
- heterogeneous 数据至少 10% episode 含重复物性；另有 homogeneous 负对照。
- 审计 detection permutation bias <0.04、|property-position correlation| <0.05、同步地址置换的 metric equivariance error <1e-7。
- 任一失败先修生成器，不启动训练。

## M1a：Privileged headroom（MUST）

- 同一数据和模型预算训练 shared dynamics 与 GT-property oracle，各 3 seeds。
- 困难 heterogeneous-ID split：oracle assignment gain >=5pp 且 wrong-object 下降才进入 M1b。
- 此结果只说明 headroom，不支持 IFB。

## M1b：Allowed-history method gate（MUST）

- `system_id`：共享 history encoder 估计 `q(mass,friction|H_i)`；训练时可用 simulator properties 做辅助监督，测试时不可读取 property。
- `full_history`：参数不少于 system-ID 的 GRU，直接从同一 `H_i` 和 query action 预测效果分布。
- `full_history_aux`：同一 GRU 额外接受完全相同的 property auxiliary supervision；method gate 使用两条 full-history 基线中更强者，排除额外监督解释。
- 各 3 seeds，matched epochs/optimizer/data；报告参数量、NLL、assignment、wrong-target、ECE、risk-coverage。
- PASS：system-ID 相对 GRU assignment >=3pp 且 wrong-target 相对下降 >=15%；三 seeds 方向一致。
- KILL：未过门则不接 OA-WAM、EvoScene 或 pi0.5。

## M2：反解释（仅 M1b PASS）

- shuffled per-address history；global pooled history；matched-capacity MLP；homogeneous/repeated-property split。
- hierarchical/paired bootstrap 按 episode 配对、按训练 seed 汇总。

## M3：对象选择代理闭环（仅 M2 PASS）

- 多模板任务：推动到目标区、相似容器取回、遮挡后继续操作。
- belief 只决定目标地址，控制动作固定；比较 GRU、system-ID、oracle identity。
- 固定 coverage 下 wrong-object action 相对下降 >=20%，不显著增加 stagnation。

## 预注册执行顺序与预算

1. M0 smoke + 2k generator/audit：CPU，预计 <1h。
2. M1a 3+3 seeds：GPU 2/3 优先；若 0/1 启动前逐卡空闲则并行，预计 <8 GPUh。
3. 自动聚合 gate；只有 PASS 才运行 M1b 3+3 seeds，预计 <12 GPUh。
4. M1b 失败立即停止；成功才另行生成更大数据并进入 M2。

Pilot 在 32 GPUh 前硬停扩展。所有结果写个人目录 JSON/NPZ；模拟器持久 body identity 是唯一 ground truth。
